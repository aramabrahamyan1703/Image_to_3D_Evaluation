# image-to-3d-eval

A practical benchmark and evaluation pipeline for **single-image 3D reconstruction**.
We compare three open-source feed-forward methods on the same 100-object subset of
[Google Scanned Objects (GSO)](https://research.google/blog/scanned-objects-by-google-research-a-dataset-of-3d-scanned-common-household-items/),
using one rendered front view of each object as input and the original GSO
mesh as ground truth.

> **Course:** DS 235 — Generative AI · American University of Armenia · Spring 2026
> **Project type:** Option 2 (Practical Research)
> **Author:** Aram Abrahamyan

## What this is

| Method (paper) | Year | Why we picked it |
|---|---|---|
| [TripoSR](https://github.com/VAST-AI-Research/TripoSR) (Tochilkin et al.) | 2024 | Single-stage triplane-NeRF baseline; fastest. |
| [InstantMesh](https://github.com/TencentARC/InstantMesh) (Xu et al., ECCV'24) | 2024 | Diffusion-then-LRM pipeline; highest-quality geometry. |
| [Stable Fast 3D](https://github.com/Stability-AI/stable-fast-3d) (Boss et al., CVPR'25) | 2025 | Adds material/lighting decomposition; production output. |

All three take **one RGB image** and produce a **textured 3D mesh** in a few
seconds. We run each on the *same* 100 inputs and report:

- **Image fidelity** (PSNR, SSIM, LPIPS, CLIP)
- **Input alignment** (Silhouette IoU)
- **Multi-view consistency** (CLIP across rendered views)
- **Geometric accuracy vs. ground truth** (Chamfer-L1, F-Score@τ, Normal Consistency)
- **Mesh quality** (face count, watertightness, winding)

A property-based slice (`scripts/slice_by_property.py`) breaks every metric
down by **thickness / surface type / material**, so we can see which
*kind of object* each method handles best — not only which is best on average.

## Installation

The pipeline runs on **Linux**, **macOS** (CPU-only), and **Windows** (with WSL2 strongly recommended for CUDA).
Inference of the three image-to-3D models is *not* part of this repo; we evaluate the meshes those models produce.

### 1. Create an environment

```bash
# pick one
python -m venv .venv && source .venv/bin/activate    # Linux / macOS
python -m venv .venv && .venv\Scripts\activate        # Windows (PowerShell)
# or
conda create -n eval3d python=3.10 -y && conda activate eval3d
```

### 2. Install the package

```bash
pip install --upgrade pip
pip install -e .
```

### 3. Install PyTorch3D separately

PyTorch3D wheels depend on your CUDA / PyTorch version, so it cannot be pinned in `pyproject.toml`.

```bash
# CPU or CUDA, on Linux / macOS:
pip install "git+https://github.com/facebookresearch/pytorch3d.git@stable"
```

On **Windows**, PyTorch3D is easiest under WSL2; native Windows installs require Visual Studio Build Tools and a matching CUDA toolkit (see [PyTorch3D INSTALL.md](https://github.com/facebookresearch/pytorch3d/blob/main/INSTALL.md)).

### 4. Smoke test

```bash
pytest tests/test_geometry.py -q     # mesh-only, runs on CPU, no model downloads
```

The full smoke test (`tests/test_pipeline_smoke.py`) additionally needs `pytorch3d`, `lpips`, and `open_clip` and will be skipped if any are missing.

## Reproducing our results

1. **Get the inputs and ground-truth meshes.** Follow `data/README.md`. Briefly:
   - Download our 100-object GSO subset (IDs in `data/eval_subset.txt`).
   - Render or otherwise produce a single front-view PNG per object → `data/inputs/<sample_id>.png`.
   - Place the GSO ground-truth meshes → `data/references/<sample_id>.obj`.

2. **Generate predicted meshes** with each method (per their own repos), saving as
   `data/meshes/<method>/<sample_id>.obj`.

3. **Run evaluation** for each method:

   ```bash
   python scripts/run_eval.py \
       --inputs     data/inputs \
       --meshes     data/meshes/triposr \
       --references data/references \
       --out        runs/eval/triposr \
       --views 8 --image-size 512 --device cuda
   ```

   Repeat with `--meshes data/meshes/sf3d --out runs/eval/sf3d` etc.

4. **Build the cross-method reports**:

   ```bash
   python scripts/report.py     runs/eval/triposr runs/eval/sf3d runs/eval/instantmesh \
       --out runs/eval/comparison.md
   python scripts/report_html.py runs/eval/triposr runs/eval/sf3d runs/eval/instantmesh \
       --out runs/eval/report.html
   ```

5. **Property-based breakdown** (see *Feedback follow-up* below):

   ```bash
   python scripts/slice_by_property.py \
       --runs   runs/eval/triposr runs/eval/sf3d runs/eval/instantmesh \
       --labels data/property_labels.csv \
       --out    runs/eval/by_property.md
   ```

## Headline results (n = 100)

The full table lives in [`runs/eval/comparison.md`](runs/eval/comparison.md) (markdown) or [`runs/eval/report.html`](runs/eval/report.html) (formatted). Excerpt:

| Metric | TripoSR | SF3D | InstantMesh |
|---|---:|---:|---:|
| Chamfer-L1 ↓ | **0.129** | 0.185 | 0.132 |
| F-Score @ 2 % ↑ | 0.257 | 0.166 | **0.275** |
| Normal Consistency ↑ | **0.642** | 0.526 | 0.627 |
| Silhouette IoU ↑ | 0.104 | **0.271** | 0.119 |
| LPIPS ↓ | **0.455** | 0.491 | 0.507 |
| Watertight % ↑ | 0 % | 0 % | **38 %** |

**Each bolded number maps directly to one finding** in the slides — see [`docs/FEEDBACK.md`](docs/FEEDBACK.md) for the metric → conclusion chain.

## Feedback follow-up

The first round of feedback for the presentation flagged four issues. This final submission addresses them as follows:

| Feedback | Where it's addressed |
|---|---|
| Slides too text-heavy | `slides/presentation.tex` rewritten — body text is now ≤ 7-word bullets per slide; speaker notes carry the detail. |
| 3D / NeRF terminology not introduced | New "3D primer" slide defines mesh, NeRF, triplane, view rendering before any method is shown. |
| Metrics (NC, W, Sil-IoU, …) not introduced | Two dedicated metric-definition slides — every metric used later is defined, with formula + plain-language explanation. |
| Results → conclusion link unclear | Each result slide pairs a metric with the *specific* conclusion it implies; results table uses arrows ("F@2 % ↑ → InstantMesh wins because diffusion stage recovers occluded surfaces"). |
| Property-based metric report missing | `scripts/slice_by_property.py` + `data/property_labels.csv` (30-object hand-labelled subset) → per-property breakdown in `runs/eval/by_property.md` and a dedicated slide. |
